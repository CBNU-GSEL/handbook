# Compute-use rules

- Use your own GSEL account and personal workspace. Do not share sign-in
  details or access another researcher's work without permission.
- Use Coder for development and small local checks. Submit sustained CPU or
  GPU experiments through Gateway.
- Request the CPU threads, RAM, and VRAM the workload needs. Keep program
  parallelism within the request and provide a realistic runtime estimate.
- Run a small smoke experiment before a full run. Check failures before
  retrying and avoid duplicate submissions.
- Cancel work you no longer need and stop idle Coder workspaces.
- Keep code, dependencies, parameters, and results traceable to the submitted
  revision. Check outputs before reporting success.
- Follow the member guide for data access and retention. Do not copy or
  publish restricted data without approval.
- Keep credentials and restricted research material out of AI prompts,
  repositories, logs, and public support reports. Review AI-generated code
  and commands before relying on them.
- Use the documented access and submission routes. Report access or resource
  problems through the internal support channel.
